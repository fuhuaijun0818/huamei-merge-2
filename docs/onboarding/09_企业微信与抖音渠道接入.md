# 企业微信与抖音接入智能体

本文说明如何把外部渠道消息接入售前智能体。平台账号、应用ID、Secret、Token、AESKey 和授权审批可以暂时留空；留空时渠道状态会显示 `not_configured`，不会影响网页前台、管理后台和现有 API。

## 1. 先明确接入边界

```text
企业微信 / 抖音平台
        │ 官方回调
        ▼
公网 HTTPS 反向代理（只暴露白名单回调路径）
        │
        ▼
售前智能体服务 4180
        │ 统一消息协议
        ▼
轮次理解、知识检索、留资、人工接管与安全门禁
```

4180 仍应只位于私有网络。公网只允许平台回调路径进入，不要把整个售前服务直接暴露。

当前代码支持：

- 企业微信自建应用加密回调：SHA-1 验签、AES-256-CBC 解密、URL 验证、文本消息、加密被动 XML 回复或应用消息主动回复。
- 抖音授权连接器回调：时间戳、Nonce、HMAC-SHA256 验签，文本消息进入智能体，标准化回复提交到配置的授权回复连接器。
- 企业微信和抖音消息都固定绑定服务端配置的租户，消息正文不能切换租户。
- 人工已经接管时，两个渠道都会抑制 AI 对客回复。

尚未包含：

- 企业微信“微信客服”的 `sync_msg` 拉取、游标持久化和客服消息发送。若需要直接承接微信外部客户，还需在自建应用模式之外增加微信客服连接器。
- 抖音开放平台各产品线的具体 OAuth、授权续期和官方发送 API。当前通过已授权连接器接入，连接器需按获批的产品能力实现。
- 平台账号资质、消息权限、模板或私信权限申请。这些只能在企业管理员或开放平台后台完成。

## 2. 企业微信操作步骤

### 2.1 在管理后台取得配置

1. 企业微信管理后台创建或选择“自建应用”。
2. 记录企业ID、应用 AgentId 和应用 Secret。
3. 在应用“接收消息”设置中生成 Token 和 EncodingAESKey。
4. 准备一个具有有效证书的公网 HTTPS 域名。

对应变量：

```dotenv
HUAMEI_CHANNEL_WECOM_CORP_ID=
HUAMEI_CHANNEL_WECOM_AGENT_ID=
HUAMEI_CHANNEL_WECOM_SECRET=
HUAMEI_CHANNEL_WECOM_TOKEN=
HUAMEI_CHANNEL_WECOM_ENCODING_AES_KEY=
HUAMEI_CHANNEL_WECOM_TENANT_ID=huamei-shanghai
HUAMEI_CHANNEL_WECOM_REPLY_MODE=passive
```

这些值只写入本机 `.env.local` 或受控密钥系统，不提交 Git，也不要放入浏览器代码。

### 2.2 配置公网回调地址

自建应用接收消息地址：

```text
https://你的域名/v1/channels/wecom/webhook
```

反向代理必须保留查询参数 `msg_signature`、`timestamp`、`nonce` 和 `echostr`，并把请求转发到内部售前服务 4180。建议只开放这一条回调路径，不开放 `/v1/handovers`、管理端或其他服务接口。

Caddy 示例：

```caddyfile
handle /v1/channels/wecom/webhook {
    reverse_proxy acquisition:4180
}

handle /v1/channels/douyin/webhook {
    reverse_proxy acquisition:4180
}
```

### 2.3 选择回复模式

- `passive`：服务同步返回加密 XML，适合能在企业微信要求时间内完成的一轮回答。默认使用此模式。
- `active`：服务调用企业微信应用消息接口发送回复。适合回答耗时较长或平台不接受被动回复的场景。

当前主动发送使用自建应用 `message/send`。它适合企业内部成员或该应用实际支持的消息对象；“微信客服”外部用户需要另行接入客服专用 API，不能把本模式当作完整微信客服实现。

### 2.4 验证

先执行：

```sh
npm run test:channel-connectors
npm run start:acquisition
```

使用具有 `service:read` 权限的内部调用方查看：

```text
GET /v1/channels
```

企业微信显示 `status=ready` 后，再在企业微信后台保存回调地址。平台会发起 GET 验证；通过后发送“我想了解热玛吉”测试消息。

可接受的实际结果：

- 服务返回签名验证、解密和租户核对成功。
- 同一企业用户形成稳定 `conversation_id`。
- 回复来自已发布知识，并经过医疗边界检查。
- 人工接管后企业微信不再收到 AI 回复。
- 日志和响应中不出现 Secret、Token、AESKey 或客户完整手机号。

## 3. 抖音操作步骤

### 3.1 先在开放平台申请能力

在抖音开放平台或对应业务后台申请所需产品能力，至少需要：

- 事件或消息回调地址配置能力；
- 私信或客服消息读取权限；
- 回复消息发送权限；
- 企业、账号和门店与业务租户的绑定关系。

具体权限名称随抖音产品线变化，以申请通过后的官方文档为准。未取得权限时相关变量保持为空。

### 3.2 部署授权连接器

抖音官方回调通常需要按具体产品完成签名、解密、事件拉取或授权续期。为避免把未核实的产品差异硬编码进智能体，当前采用一个授权连接器中转：

```text
抖音平台 → 抖音授权连接器 → 智能体验证回调
                              ↓
                       智能体处理消息
                              ↓
                    授权连接器发送回复
```

智能体入站地址：

```text
https://你的域名/v1/channels/douyin/webhook
```

连接器向该地址发送 JSON，并增加：

```text
X-Huamei-Timestamp: Unix秒
X-Huamei-Nonce: 一次性随机字符串
X-Huamei-Signature: hex(HMAC-SHA256(secret, timestamp + "\n" + nonce + "\n" + rawBody))
```

支持的最小事件字段：

```json
{
  "event_id": "抖音事件ID",
  "conversation_id": "会话ID",
  "open_id": "用户OpenID",
  "text": "客户消息",
  "event_type": "im_message"
}
```

签名有效期为五分钟。连接器必须保证相同事件使用同一 `event_id`，智能体将其用于会话和回复连接的幂等控制。

### 3.3 配置平台变量

```dotenv
HUAMEI_CHANNEL_DOUYIN_APP_ID=
HUAMEI_CHANNEL_DOUYIN_APP_SECRET=
HUAMEI_CHANNEL_DOUYIN_WEBHOOK_SECRET=
HUAMEI_CHANNEL_DOUYIN_VERIFY_TOKEN=
HUAMEI_CHANNEL_DOUYIN_TENANT_ID=huamei-shanghai
HUAMEI_CHANNEL_DOUYIN_REPLY_WEBHOOK_URL=
HUAMEI_CHANNEL_DOUYIN_REPLY_TOKEN=
```

`HUAMEI_CHANNEL_DOUYIN_REPLY_WEBHOOK_URL` 是连接器的发送接口。智能体把标准化回复 POST 到该地址，并携带 `Authorization: Bearer <REPLY_TOKEN>` 与 `Idempotency-Key`。响应建议为：

```json
{
  "delivered": true,
  "message_id": "平台消息ID"
}
```

若连接器只是异步受理，可返回 HTTP 202；此时智能体记录 `accepted`，不能将其描述为已送达。

### 3.4 URL 验证

连接器可以在以下请求中任选一种方式完成挑战校验：

- 带 `token` 或 `hub.verify_token`，值与 `HUAMEI_CHANNEL_DOUYIN_VERIFY_TOKEN` 一致；
- 使用上面的 HMAC 签名请求头。

验证通过后，智能体原样返回 `challenge`。

## 4. 联调顺序

1. 先跑本地契约测试，不连接真实平台：

```sh
npm run test:channel-connectors
```

2. 用假事件分别验证文本消息、重复事件、非文本事件、人工接管、超长消息、错误签名和过期时间戳。

3. 配置测试企业或测试抖音账号，使用虚构客户和公开知识完成首次真实收发。

4. 检查后台是否出现相同 `conversation_id`，再验证留资、人工接管、预约意向及知识撤回。

5. 真实平台测试在报告中单独记录为“真实渠道验收”；本地 Mock 通过不能替代平台收发证明。

## 5. 常见阻塞

| 现象 | 原因 | 处理 |
|---|---|---|
| 渠道状态 `not_configured` | 必填变量为空 | 补齐变量并重启售前服务；不要在前端传租户 |
| 企业微信 URL 验证失败 | Token/AESKey 不一致或代理丢失查询参数 | 核对后台配置与代理转发 |
| 企业微信返回 401 | SHA-1 签名无效 | 检查 timestamp、nonce、密文和 msg_signature |
| 企业微信返回 403 | receive_id 与企业ID不一致 | 检查 CorpID 和 APP 是否属于同一企业 |
| 抖音返回 401 | 时间戳过期或 HMAC 不一致 | 使用原始请求体重新计算签名，不重新序列化 JSON |
| 抖音回复未送达 | 连接器仅返回受理或发送接口失败 | 查看连接器回执，不得把 202 当作已送达 |
| 人工接管后没有 AI 回复 | 系统正确执行了 AI 静默 | 由当前接管顾问回复，结束后再恢复 AI |

## 6. 相关代码

- `server/acquisition-channel-connectors.mjs`：企业微信验签/AES、抖音 HMAC、回调处理和回复连接。
- `server/acquisition-channel-adapters.mjs`：渠道标准入站、出站格式与配置状态。
- `server/acquisition-service-server.mjs`：公开平台回调路由；服务调用方鉴权之前只放行带平台签名的回调路径。
- `server/acquisition-service-openapi.mjs`：回调接口规范。
- `tests/acquisition-channel-connectors.mjs`：加密、签名、接管抑制与抖音中转回归。
